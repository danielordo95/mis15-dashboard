- **2026-08-24 — Puente remote-devices no crea carpetas vacías [fuente: ejecución propia]:** Las herramientas disponibles para escribir en el Mac del usuario (`device_commit_files`, `device_stage_files`, `device_list_dir`) solo pueden crear/escribir archivos; no existe una operación de "mkdir" para materializar una carpeta vacía en el dispositivo del usuario cuando no hay `device_bash` disponible en la sesión. **Por qué importa:** carpetas que deben quedar vacías por diseño (p.ej. `directives/`, `execution/`, `.tmp/` en el setup inicial de este workspace) no aparecen físicamente en el Mac del usuario hasta que se escribe el primer archivo real dentro de ellas. No es un error — es la forma normal en que el sistema operativo crea directorios padre al escribir un archivo — pero hay que anticiparlo y comunicarlo al usuario en vez de asumir que "estructura creada" implica carpetas visibles en su disco.

- **2026-08-24 — Sandbox de Cowork sin salida de red a GitHub/Vercel [fuente: ejecución propia]:** Se probó un fine-grained PAT de GitHub válido desde este entorno (`git clone`, llamadas directas a `api.github.com`) y ambas fallaron: el proxy de red de la sesión intercepta el tráfico hacia GitHub y responde "session scope unavailable" / 502, pidiendo una herramienta `add_repo` que no está expuesta en sesiones de Cowork. Una conexión directa a `vercel.com` / `api.vercel.com` ni siquiera conecta (timeout) — el egress de red está en una lista blanca que sí incluye `registry.npmjs.org` pero no aloja destinos de deploy/git hosting. **Por qué importa:** el paso de "commit + push automático" descrito en el spec original (arquitectura, sección 4) NO es alcanzable desde esta sesión sin importar qué tan bien esté configurado el token — no hay que perder tiempo reintentando con otro PAT o método de auth por curl/git directo. La solución adoptada: Cowork deja todo listo en la carpeta local (`data.json` + `index.html` regenerados) y el usuario hace `git add/commit/push` manualmente (3 comandos, o un click en GitHub Desktop) cada vez que actualiza — Vercel sigue redeployando 100% automático vía su integración nativa con Git, así que el cliente final nunca nota el paso manual. Documentado en `README.md`.

- **2026-08-24 — "Alcance" (reach) no es sumable entre días [fuente: ejecución propia, validado con cross-check contra la fila resumen del CSV]:** Sumar el "Alcance" diario del export de Meta a través de un rango de fechas sobreestima el alcance real en ~85% en los datos de prueba (74.255 reportado por Meta para el rango completo vs. 137.840 al sumar las filas diarias) porque la misma persona puede ser alcanzada varios días distintos y Meta no permite deduplicarla desde este tipo de export. **Por qué importa:** el dashboard v2.0 muestra "Alcance" siempre etiquetado como "acumulado, aproximado" con una nota explícita, nunca como alcance único real — evita que el cliente lea el número como si fuera el alcance deduplicado que vería en Ads Manager. Todas las demás métricas de suma (gasto, resultados, impresiones, clics, conversaciones, interacciones) sí cuadraron con menos de 0,1% de diferencia contra la fila resumen del CSV.
